# Direct named double row addresses

- C11 N1570 §6.5.2.1 defines `a[i]` as `*((a)+(i))`; §6.5.3.2 says `&a[i]` behaves as `a+i` without evaluating the implied indirection. Source: https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf .
- Bound the new slice to `&values[i]` where `values` is a named fixed two-dimensional `double[R][C]` object. The expression produces the same `PointerValue::Array2DRow` and width/owner metadata as `values+i`; no host pointer or new storage representation is needed. Do not conflate `&values` (pointer to whole 2D object) with `&values[i]` (pointer to a row), or admit aggregate-field row addresses implicitly.
- Before-state: `double (*row)[2] = &values[1];` failed with `two-dimensional array 'values' requires a second index`; native C11 accepted it and the example returned 15. Two focused interpreter tests cover address/decay equality and subtraction, binary64 access, `sizeof(&values[marker++])` non-evaluation, const, width, expired owner, and out-of-bounds selection. The registered strict C11 fixture compares portable exit 15.
- Reuse `AddressOfArray` only when the named runtime value is a two-dimensional double array. Its runtime branch evaluates the index once and offsets the existing row pointer; the scalar-pointer rejection gate must likewise exempt only the same shape. Leave aggregate-field row addresses and whole-row object-byte addresses excluded until their route-specific type/owner and non-evaluating support is proved.
- Verify with `cargo test --test interpreter direct_double_named_row_address -- --nocapture` and the actual `cargo test --test c_compat -- --nocapture` function; filtering the oracle by fixture filename runs zero tests.
